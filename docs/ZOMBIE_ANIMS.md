# 殭屍動畫庫 Zombie animation library

`game/assets/zombies/anims.glb` holds every zombie AnimationClip on the MPFB2 **game_engine** skeleton
(UE-mannequin bone names). Characters (`game/assets/zombies/<type>.glb`, built by the character
pipeline) use the same skeleton, so the clips play on them directly; `game/src/zombies/retarget.js`
re-bakes them per model to absorb rest-pose / proportion differences.

## 1. Conventions

| Item | Value |
|---|---|
| Skeleton | 53 bones: `Root`, `pelvis`, `spine_01..03`, `neck_01`, `head`, `clavicle/upperarm/lowerarm/hand_l/r`, 15 finger bones per hand, `thigh/calf/foot/ball_l/r` |
| Rest pose | default MakeHuman body (pelvis 0.874 m, height ~1.66 m), Blender bone frames (local +Y runs head -> tail), glTF Y-up |
| Space | metres, +Y up, character faces **+Z**, `Root` on the ground between the feet, identity rotation |
| Rate | sampled at 30 fps, linear keys (constant tracks collapsed to one key) |
| Tracks | a rotation track for every bone except `Root` in **every** clip (so cross-fades never leave stale bones) + `pelvis.translation` |
| Root motion | none: clips are in place (pelvis keeps bob / sway). Exceptions are listed per clip (`rootMotion`, `travel`, `climbSpeed`) |
| Bones | the GLB has a mesh-less skin, so `GLTFLoader` creates real `THREE.Bone`s (needed by `retargetClips`) |

### Metadata (`gltf.scene.userData`)

```js
{ kind: 'zombie-animation-library', skeleton: 'mpfb2-game_engine', fps: 30, up: '+Y', forward: '+Z', units: 'm',
  clips: { walk_a: { duration, loop, speed, source, notes, events?, rootMotion?, travel?, climbSpeed? }, ... } }
```

- `speed` (m/s) - treadmill speed of a locomotion loop on the default body: a planted foot moves backwards at
  exactly this speed, so feet stick to the ground when the zombie moves at `speed`. For a character whose pelvis
  rest height is `h`, use `speed * h / 0.874` and set `action.timeScale = moveSpeed / thatSpeed`.
- `events` - seconds into the clip: `hit` (damage frame of attacks), `grab`, `launch` / `land` / `takeoff`,
  `spit` (spawn the projectile from the head), `scream`, `ground` (body hits the floor).
- `rootMotion` - where the pelvis ends up relative to the start (metres, deaths only); `travel` - how far the
  game should carry the zombie between `launch` and `land` (attack_lunge); `climbSpeed` - vertical speed the game
  applies while `climb` loops.

### Playing them (three.js)

```js
const lib = await loader.loadAsync('assets/zombies/anims.glb');
const meta = lib.scene.userData.clips;
const clips = retargetClips(lib.animations, lib.scene, zombie.scene);   // game/src/zombies/retarget.js
const mixer = new THREE.AnimationMixer(zombie.scene);
const walk = mixer.clipAction(THREE.AnimationClip.findByName(clips, 'walk_b')).play();
walk.timeScale = moveSpeed / (meta.walk_b.speed * pelvisHeight / 0.874);
const hit = mixer.clipAction(THREE.AnimationClip.findByName(clips, 'hit_left'));
hit.setLoop(THREE.LoopOnce).clampWhenFinished = true;   // one-shots: fade in 0.1-0.15 s, fade back to idle/walk
```

Hit reactions start and end on the `idle` pose, so they can also be made additive
(`THREE.AnimationUtils.makeClipAdditive(clip, 0, idleClip)`) and layered over walking. `knockdown` ends exactly on
the first frame of `get_up`. `death_*` end lying still (hold the last frame or hand over to ragdoll).

## 3. Pipeline (`tools/assets/zombies/anim/`)

```
node tools/assets/zombies/anim/fetch.mjs       # downloads sources to tools/assets/zombies/src/ (git-ignored)
node tools/assets/zombies/anim/build.mjs       # -> game/assets/zombies/anims.glb (+ docs table, CREDITS section)
node tools/assets/zombies/anim/check.mjs --model game/assets/zombies/walker_a.glb
node tools/assets/zombies/anim/mannequin.mjs   # preview mannequin -> game/dev/mannequin.glb (dev only)
node tools/build-anim-preview.mjs              # preview bundle -> game/anim-preview.js
```

| File | Role |
|---|---|
| `skeleton.mjs` | game_engine rest pose from `rig.game_engine.json` (Blender bone maths re-derived: minimal-arc Y -> bone vector, then roll), FK |
| `bvh.mjs` | BVH parser (any channel order) -> world-space source motion, resampled to 30 fps |
| `gltf-read.mjs` | minimal GLB reader + animation sampler (LINEAR / STEP / CUBICSPLINE) |
| `sources.mjs` | Quaternius UAL1 (Rigify `DEF-*` names) / UAL2 (UE names) and CMU loaders + bone maps |
| `retarget.mjs` | world-space retargeter: `G_t = H * G_s * inv(W_s) * A * W_t` with per-bone rest alignment `A` (target rest direction -> source rest direction, so T-pose CMU drives the A-pose target), heading normalisation, leg-length root scaling |
| `clip.mjs` | crop / retime / mirror / smoothing, linear root-trend removal (in place, keeps bob & sway), loop search (pose + velocity window) and seam cross-fade into the frames that precede the loop start |
| `ik.mjs` | two-bone IK, heel/toe contact detection and **foot locking** (planted point pinned to a treadmill-moving anchor, cyclic), ground fitting, treadmill-speed estimation, stride warping |
| `pose.mjs` | keyframe DSL: per-bone degree offsets in character axes relative to the parent (`_r` keys mirrored, symmetric keys), Catmull-Rom curves, planted-feet / hand IK channels, loop-safe noise |
| `zombify.mjs` | zombie post-process: slumped spine, tilted/lolling head, dropped shoulder + asymmetric arm hang, clawed fingers, loop-safe twitches |
| `clips-loco.mjs`, `clips-action.mjs`, `clips-late.mjs` | the 28 clip recipes |
| `metrics.mjs`, `plot.mjs` | foot-slide / pop / seam metrics printed by the build; `--plot` writes a foot-contact chart |
| `check.mjs` | verification (clip list, bone targets, unit quaternions, closed loops, model skeleton) |
| `credits.mjs` | the zombie-animation section of `docs/CREDITS.md` |

## 4. Notes for the game code

- **Speed sync.** `game/src/zombies/defs.js` currently uses hand-picked `nominal` speeds (walk 1.0-1.1, run 3.6,
  runner 5.0). The clips' real treadmill speeds on the default body are walk_a 0.94, walk_b 0.46, walk_c 0.68,
  walk_limp 0.43, run 3.80, sprint 5.48, crawl 0.32 m/s (x pelvis-height ratio, ~1.12 for `walker_a`). Reading
  `userData.clips[name].speed` instead avoids foot sliding; zombies that should shuffle faster than a clip's
  natural speed can still use `timeScale` up to ~1.6 before it looks hurried.
- **One-shots** end on (or close to) the `idle` pose; fade back to locomotion over 0.15-0.25 s. `attack_lunge`
  and `leap` are in place: move the zombie forward between their `launch`/`takeoff` and `land` events.
- **Deaths / knockdown** keep the body where it falls (pelvis drift listed as `rootMotion`); keep the zombie's
  root where it was, hold the last frame (`clampWhenFinished`) or switch to ragdoll after `events.ground`.
- **`crawl` / `crawl_attack`** are for legless crawlers (legs drag behind the body, prone); `climb` assumes a
  wall about 0.4 m in front of the root.
- **Per-type clip overrides** (`defs.js` `anim.over`, applied in `Zombie.playOnce` for every caller, replicated
  clips included): a string plays another clip, `null` plays none (the current clip goes on, the procedural flinch
  still plays), `{ from, speed, fade }` tweaks one. The prone `crawler` uses it so it never pops upright: no
  hit / stagger / knockdown clip, every death is the face-down end of `death_front` (from 0.95 s, 0.4 s fade = the
  collapse), and `leap` starts in its crouch (0.3 s, x1.4) so takeoff -> land fits the 0.65 s the game moves it.
  The crawler model has legs (on all fours), so the legless `crawl` drag and the upright `leap` flight are a
  compromise until a quadruped crawl / pounce / death set exists.
- Clip tracks never touch `Root`; if the character's armature has a rotated root (Blender Z-up export) use
  `retargetClips`, which handles it.

## 5. Known limitations

- `walk_b` (CMU 104_41) is a genuine foot-dragging shuffle: the swing toe scrapes the floor, which the slide metric
  counts as sliding (planted feet themselves are locked).
- The mocap clips were captured by human actors with full-length strides; `run` / `sprint` legs come from
  Quaternius' athletic jog / sprint with the stride warped to 68 % / 66 %, so the gait is still fairly athletic
  below the zombie upper body.
- Keyframed clips are authored on the hunched idle; on characters with very different proportions the hands of
  `bite` / `eat` / `crawl` (IK targets in metres) land a few centimetres off.
- No facial / jaw bones in the game_engine rig: screams and bites are body-only (jaw motion would need a morph).
- `death_front` is keyframed (no suitable CC0/CMU "collapse forward" take); it reads well from gameplay
  distance but is less organic than the mocap falls.
