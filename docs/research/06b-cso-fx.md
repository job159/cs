## 0. 重點摘要（TL;DR）

1. **CSO 打殭屍的回饋，靠的是「紅血＋數字＋連殺字」，不是命中閃白。** [截圖觀察][影片]
   - **血**：鮮紅、量大。噴濺精靈加上**很大的鮮紅貼花**，地面和牆面一塊可達 1–1.5 m。它比 CS2 的暗紅血更亮、更飽和，也留得更久。
   - **傷害數字**：2020-07 起全殭屍模式都有「浮動傷害」[Wiki]。數字是粗斜體加深色描邊，在頭頂**往上堆疊**，並帶殘影。
     - 分兩級：大的那一級字更大，左邊多一個爆炸星標。推測是爆擊或爆頭 [推論]。
     - 數字的字型與配色本身是可以買的「傷害字型皮膚」。
   - **連殺字**：畫面上方中央，金屬鍍鉻的斜體「N COMBO!」。10、20、30 連殺時換成銀、金、紅三種色階 [截圖觀察]。
   - **沒有命中閃白**：殭屍被打時只有退後（擊退）、減速（硬直）與受擊動作 [推論]。
   - **整身染色**只用來表示「狀態」：紅色是狂暴或硬化，綠色「＋」是被治療。
2. **殭屍技能的視覺都是「單一顏色、大面積、很好認」。** [截圖觀察][Wiki]
   - 精神殭屍：**近黑色**的大煙團，每 2 秒噴一次、共 4 次。
   - 巫毒殭屍：一群**綠色「＋」十字光球**，被治療的殭屍頭上也會出現「＋」。
   - Deimos：衝擊波是一條**黃色長尾跡**。
   - 輕型殭屍隱身後幾乎看不見，但身上**半透明的紅血漬**仍然看得到。
   - 毒液守衛（自爆型）：死亡時炸成**黃綠膿包碎塊加肉塊**。被爆頭打死則**不會爆**。
3. **Boss 招式 = 地面預兆 + 一大塊元素精靈 + 全螢幕疊圖。** [截圖觀察]
   - Revenant「煉獄」：地面衝擊後，沿一條直線**依序炸出一排火球**。
   - Revenant「地獄火雨」：滿天的**火球加上整個畫面泛橘霧**。
   - Dione 的毒息：**淡綠白色的寬錐**，會把畫面洗白。
   - Dione 觸手：地面先出現**黑色圓斑**，再從斑點刺出觸手。
   - 受到燃燒或中毒時，有**全螢幕火焰框**與**萊姆綠斑駁邊框**兩張疊圖。
4. **補給箱用「只有你看得到的藍光」做獎勵感。** [Wiki]
   - 殭屍死亡時掉落的補給箱，一開始**只有擊殺者**看得到箱蓋縫隙的藍光。約 1 分鐘後才開放給所有人。
   - 殭屍對抗模式的補給箱，在畫面上用「青色圖示＋[41m]」標出方位與距離。
   - 道具戰的補給是**懸浮旋轉的方塊**，地上有**青色齒輪光環**。
5. **升級在 CSO 只是一條文字帶**：下方中央一條半透明黑帶，寫著「Level Up! Level: 30」，沒有 3D 光環 [影片]。我們可以多做一點，但要克制，見 §9.6。
6. **神兵特效可以歸成 10 種原型**（§8），每種都有固定的疊法：
   - 光束彈道、閃電鏈、每 N 發爆炸、變形、召喚獸、近戰刀光、蓄力光束或全螢幕隧道、擊殺特效、專屬準星、課金槍口焰。
   - 時間參考值來自 GIF 逐格 [截圖觀察]：
     - Divine Blaster 的槍口焰是 45 格。前段是一道斜向金色光束，中段長出**一圈帶放射尖刺的光冠**，後段 2–3 圈細環漂散。
     - Star Chaser 的星爆約 1.7 s：藍色亮核先長出絲狀觸鬚，再碎成藍色閃點飄散。
     - 電漿彈爆炸約 0.9 s：萊姆綠亮團炸成一圈綠點。
7. **CSO 的顏色就是語言**（§2.2）：
   - 紅：傷害、狂暴、惡魔。
   - 綠：毒、治療、電漿。
   - 藍與青：冰、雷、能量。
   - 金：神聖、頂級。
   - 紫：Boss 或超越級的增益。
8. **引擎缺口**：在 06a 的 flipbook 與溫度漸層之上，還需要 8 個元件。
   - 緞帶拖尾 `trail.js`、光束 `beam.js`、閃電 `bolt.js`、地面特效 `groundfx.js`、網格特效 `meshfx.js`。
   - 全螢幕疊層（擴充 `renderer.js`）、殭屍狀態光殼（材質 uniform）、傷害數字與連殺字（`hud.js`）。
   - 規格見 §9.1。
9. **優先順序**（§9.10）：
   - P0：兩級傷害數字、連殺字、命中準星提示、殭屍狀態光殼、地面預兆圈、爆裂者毒爆、尖嘯者治療光環、酸液。
   - P1：光束、閃電、拖尾三個元件，加上「每 N 發爆炸」「閃電鏈」「刀光」三種神兵原型。
   - P2：召喚、隧道、全螢幕疊圖、Boss 大招。

## 2. CSO 特效的共通文法（跨例歸納）

### 2.1 技術底子：GoldSrc 精靈＋低模網格＋螢幕疊圖 [推論]

CSO 建在 GoldSrc 引擎上，後來大幅改造。它的特效幾乎都由三種東西組成：
1. **加算精靈（additive sprite）**：
   - 一般槍口焰常常只有 **2 格**，例如電漿槍與 BALROG-XI 的槍口焰 GIF 各 2 格，每格 100 ms [截圖觀察]。
   - 頂級武器改用 30–45 格的序列。
2. **低模網格配捲動 UV**：Brionac 的光龍捲是兩層透明圓筒，Lycaon 的狼靈是半透明模型，Frost Viper 的冰隧道是一支環狀網格 [截圖觀察]。
3. **全螢幕疊圖**：燃燒時整個畫面是一張火焰貼圖，中毒時是萊姆綠斑駁邊框，夜視則把整個畫面染綠 [截圖觀察]。

**對我們的意義**：
- CSO 的華麗不靠物理模擬，而是靠「**亮核＋色暈＋幾何形狀＋殘渣粒子＋地面印記＋螢幕框**」六層疊加。
- 這六層剛好都是手機上便宜的東西，見 §9.9 的預算。

## 3. 命中殭屍的回饋

### 3.1 血液

**觀察**：
- **顏色**：鮮紅偏暖。地面與牆上的血跡貼花比 CS2 亮很多，接近 (0.6, 0.05, 0.04) 的飽和紅 [影片：Omen 2:26]。
  - 舊版截圖中，地上的血點是**很小的鮮紅點**，散成一片 [截圖觀察：Self_Healing、隱身截圖]。
  - 2020 年後的版本中，有一些**很大塊**的鮮紅貼花：Omen 影片裡，地面和牆面的血跡可達 1–1.5 m。
- **噴濺**：Divine Blaster 打練習靶時，命中點是一團**密集的紅色噴濺精靈**，約 0.4 m，周圍帶暗紅絲點。上方同時浮出洋紅色的傷害數字 [截圖觀察]。
- **殭屍視角**：被殭屍化後，畫面整個偏粉紅紅，並蓋上一層暗紅血污 [截圖觀察：Kill_by_zb_granade]。
- **地區差異**：中國版為了審查，替換了血腥的殭屍模型 [Wiki]。血的顏色有沒有改 [不確定]。

**與 CS2 的差別**：06a §9 的 CS2 血是「暗紅、有方向的液體噴濺」，殭屍用的是 (0.25, 0.02, 0.015) 的暗紅黑。
- CSO 的血更亮、更大塊，**可讀性優先**。
- 我們的取捨見 §9.3.1：預設採「CS2 的形狀＋CSO 的亮度與面積」。

### 3.2 命中閃光、狀態光殼

- **沒有看到命中閃白** [推論：多張戰鬥截圖與影片格都沒有]。殭屍受擊只有三種反應：
  1. 擊退：往後滑。
  2. 硬直：減速或停頓。
  3. 受擊動作：Heavy 殭屍幾乎不吃硬直。
- **整身染色（glow shell）只用來表示「狀態」** [截圖觀察]：
  - 毒液守衛「硬化」：整隻是**平塗的飽和紅色**，連陰影都偏紅。
  - Ganymede 與 Deimos 的「狂速」：整隻**鮮紅**。
  - 巫毒的治療對象：頭上出現綠色「＋」。範圍內隊友的名字會變綠 [Wiki]。
  - 英雄與超越級角色：角色周圍有光，畫面邊框有電光（§7.4）。

### 3.3 擊退的「看得見」

- CSO 用擊退與硬直的百分比定義武器手感（03 §3.4）。視覺上是兩件事：
  - 殭屍**整隻往後滑**，加上上半身後仰。
  - 爆炸彈會把殭屍**炸飛到空中**。BALROG-XI 的 Wiki 特別提到，它能把殭屍「在空中」擊退 [Wiki]。
- 我們的 `manager.js` 已經有 `kvel`（擊退速度）與 `flinchV`（上半身受擊）。§9.3 只補粒子與聲音，不改物理。

### 3.4 浮動傷害數字（Floating Damage）

- **歷史** [Wiki]：
  - 前身是只在少數模式出現的頭頂傷害。
  - 2020-07-23 在韓服開放給所有殭屍模式與休閒模式。
  - 商城另售「傷害字型皮膚」。
- **字型皮膚的結構** [截圖觀察：8 種皮膚圖]：
  - 每款都有兩級。**一般級**是較小的數字，出現在頭頂。另一級的字約大 1.6 倍，**左邊帶一個圖示**。把大的那一級解讀成「爆擊或爆頭」是 [推論]。
  - 圖示有幾種：爆炸星芒、閃電、蛛網、翅膀、火焰。
  - 數字都是**粗斜體**，帶明顯的**深色描邊**與**垂直漸層填色**。
  - 主色有白、金、橘、紅、桃紅、銀。
- **實際畫面** [影片：馬拉松 16:40；Boss 演進 0:20]：
  - 連射時會**同時堆疊 3–5 個數字**，新數字往上推，並帶 1–2 個半透明的**殘影**（上一幀的位置）。
  - 主色是奶白，深色描邊。有一個特別大的數字帶**藍白色**，推測是爆擊或特殊傷害 [推論]。
  - Giga Break 命中 Boss 時的數字是**橘色**、很大，就在準星旁邊。
  - Divine Blaster 命中時的數字是**桃紅色白描邊** [截圖觀察]。這代表頂級武器可以帶自己的數字配色。

### 3.5 爆頭

- **擊殺徽章**：圓形金屬徽章，裡面是紅色準心圖案 [截圖觀察：Alarm_headshot]。搭配「Headshot!」語音 [Wiki：Kill FX]。
- **傷害數字**：使用爆擊級（§3.4）[推論]。
- **玩法上的視覺後果** [Wiki]：
  - 殭屍對抗模式中，被爆頭擊殺的殭屍不能復活。
  - 毒液守衛被爆頭擊殺時**不會爆炸**，屍體直立倒下。
- 我們目前的做法：爆頭時 `blood` 量 ×1.6，大傷害會斷頭（`sever`），另有爆頭音效。這已經比 CSO 華麗，只差 HUD 的兩級數字與徽章。

### 3.6 連殺與擊殺文字

- **Kill FX** [Wiki][截圖觀察]：
  - 「1 KILL!」到「4 KILL!」：大號數字，加上金屬拉絲的斜體字，銀藍漸層。出現在畫面上方中央偏左。
  - 劇情模式的「COMBO!」：10 連殺為**銀**，20 為**金橘**，30 以上為**紅**（Re:boot 後）。
  - 影片中是「39 COMBO!」這種**大數字加 COMBO!**的紅色鍍鉻字，右上角另有一個小一號的手寫體「Perfect!」[影片：馬拉松 16:40]。
  - 「BOSS KILL!」：紅色鍍鉻字，背後有一道**水平紅色光芒**。
  - 「ROUND CLEAR!」、「HUMAN WIN!」、「ZOMBIE WIN!」：鍍鉻斜體字加角色頭像。殭屍勝利的背景有一大片血噴濺。
- **共同的字體語言**：
  - 粗黑體斜體，約 12°。
  - 五段金屬漸層：亮、暗、亮、暗、亮。
  - 深色外框，加上一道下緣陰影。
  - 原創化時，「鍍鉻斜體」這種通用風格可以用，但**字形、圖示和配色組合要自己設計**（§10）。

### 3.7 受擊方向楔形與命中準星

- **受擊方向**：玩家被打時，準星外圍約 120 px 處出現一塊**紅色梯形楔片**，指向攻擊來源，約 1 s 後淡出 [影片：Omen 2:29]。把它解讀成「受擊方向」是 [推論]，依據是 CS 1.6 本來就有紅色的受擊方向指示。
- **命中準星提示**：頂級武器標配，見 05b §3.8 與 §8.12。
- **Thunderbolt 的瞄準鏡**：有目標進入準心時，**整個準心轉紅**並發出提示音。對 NPC 不會觸發 [Wiki]。

## 9. 可實作規格（three.js r186、WebGL2、手機）

### 9.0 前提與命名

- 以 06a §11.1 的升級為前提：
  - flipbook 連續幀（`frames`、`fps`）。
  - 溫度漸層映射（`ramp`）。
  - 假法線打光的煙。
  - `atlasFx`（8×8 格）。
- 參數沿用 06a §11.3 的寫法：`n` 數量、`life` 壽命、`size→size1` 大小、`col→col1` 顏色、`v` 初速、`g` 重力、`drag` 阻力、`A` 加法混合、`α` alpha 混合、`fr` 圖集格位。
- 顏色是線性 HDR。加算層可以超過 1。alpha 層會乘上場景環境光 `uAmbient`，所以**要看起來發光的東西一律放加算層**。
- 現有預算：`Particles` 共 3000 顆（加算與 alpha 各一半），槍模投影層各 64 顆。

### 9.1 引擎新增元件（依優先順序）

**實作重點**：
- **2. 狀態光殼**：插在 `#include <emissivemap_fragment>` 之後：
  ```glsl
  float fr = pow(1.0 - clamp(dot(normal, normalize(vViewPosition)), 0.0, 1.0), 2.0);
  totalEmissiveRadiance += uShellCol * uShellAmt * mix(1.0, fr, uShellFres);
  ```
  - `uShellFres` = 0 是 CSO 式的平塗染色（硬化、狂暴），= 1 是邊緣光（菁英怪、治療閃光）。
  - 所有殭屍共用同一個程式，uniform 放在每隻殭屍的 `material.userData` 裡，用 `onBeforeRender` 寫入，所以**不會增加 shader 變體**。
- **3. 地面特效圈**：一張 `InstancedMesh` 平面，`polygonOffset`，加算混合。
  - **全部在 shader 裡程序化**，不用貼圖：用距離 `d` 與角度 `a` 組合出環（`smoothstep` 帶狀）、刻度（`step(fract(a*N), w)`）、齒輪（`r + 0.04*step(0.5, fract(a*12))`）、扇形填充（`a < fill*2π`），還有 fbm 斑點。
  - 每個 instance 帶 `kind`、`r`、`life`、`col`、`fill`。
  - 這和 05b §8.9 的貼圖法陣互補：法陣用原創符文貼圖，其他圈全部程序化。
- **4. 緞帶拖尾**：環形緩衝區，每個節點存兩個點（刀根與刀尖，或是中心點加攝影機朝向的寬度）。
  - 頂點 shader 依年齡算 alpha 與寬度。
  - 一個 `BufferGeometry` 合併最多 32 條拖尾，用 `addUpdateRange` 只更新有變動的那段。
- **5. 光束**：一個攝影機朝向的四邊形條帶。長軸是 `to - from`，寬度方向是 `cross(axis, viewDir)`。
  - 片段 shader：`core = exp(-pow(v*2-1, 2)*40)`，`glow = exp(-pow(v*2-1, 2)*4)`，分段紋理 `0.75 + 0.25*sin((u*len - t*scroll)*6.28*bandFreq)`。
  - 加算混合。一個 beam = 1 次 draw，也可以把所有 beam 合成一個 instanced 物件。
- **6. 閃電**：中點位移遞迴 4 層，最多 17 個點，轉成條帶交給 beam 渲染。
  - 每 `regen` 秒重新生成一次。生成之間用 `sin(t*60 + i)` 微抖，避免畫面凍住。
- **8. 全螢幕疊層**：全部在合成 pass 裡程序化，不用貼圖：
  - 噪聲：`n = fbm(uv*vec2(3,5) + vec2(0, -time*0.6))`。
  - 邊緣遮罩：`e = smoothstep(0.18, 0.55, r2 + n*0.12)`。
  - 各種疊層的配色見 §9.8。這延續 05b §8.11 的 `uEdgeColor`、`uEdge`、`uZoomBlur`。

### 9.3 命中殭屍（P0）

#### 9.3.1 血（在 06a §11.3.6 之上調整）

**堆疊規則**（照 CSO 的觀察）：
- 同一個目標 0.15 s 內的新數字，從上一個數字的上方 18 px 處出現（往上疊）。
- 同一個目標最多同時顯示 4 個，第 5 個開始和最上面那個**合併**，延續 03 §4.9 的 0.3 s 合併原則。
- 全畫面上限 24 個。

**實作**：
- 目前用 DOM（`.dmgnums .dn`）。24 個以內，DOM 加 `transform: translate3d()` 與 `opacity` 就夠，**不要用 CSS `filter`**。
- 描邊用 `-webkit-text-stroke`，或 4 方向的 `text-shadow`。漸層用 `background-clip: text`。殘影用同一個元素加兩個 `::before`／`::after`，靠 CSS 變數 `--dy1`、`--dy2` 位移。
- 數字很多的武器（機槍、霰彈）想改成 WebGL 時，用 §9.2 的字型圖集加 instanced 四邊形，每個字元一個 instance。
- **頂級武器專屬數字配色**：`def.dmgSkin = 'holy'｜'abyss'｜…`。例如聖輝系是白金（白填、金描邊），深淵系是桃紅（#ff4fb0，白描邊），對應 Divine Blaster 那種桃紅數字 [截圖觀察]。

#### 9.7.2 閃電鏈（JANUS-7 B 形態、Gungnir 式）

- **主鏈**：`bolt(anchor, target, { col: 核心, glow: 色暈, levels: 4, jitter: 0.1, branches: 2, regen: 0.04, life: 持續 })`。
  - `anchor`：槍上的放電點。槍模要提供一個 `glow_core` 節點，投影成世界座標後當作起點。
  - **寬度**：JANUS 式用**粗而柔**的光帶（wCore 0.04，wGlow 0.22，jitter 0.06，levels 3）。Gungnir 式用**細而分岔多**的光帶（wCore 0.015，wGlow 0.1，jitter 0.12，levels 4，branches 3）。
  - 色票：
    - JANUS 黃：核心 (6, 3.6, 0.6)，色暈 (2.2, 1.0, 0.1)。
    - 遠古紅：核心 (6, 1.0, 0.5)，色暈 (2.4, 0.2, 0.1)。
    - Gungnir 青：核心 (1.5, 4, 8)，色暈 (0.3, 1.2, 3)。
    - 聖金：核心 (5, 3.4, 1)，色暈 (2, 1.2, 0.2)。
- **末端爆星**：A，`atlasPremium` 3（尖刺光冠），size 0.35–0.5，rot 隨機，每次 regen 換角度，col = 核心色。另外每 0.08 s 噴 3 顆火花。
- **槍上電弧**：2–3 條短 `bolt`，長 6–10 cm，繞著放電點隨機方向，regen 0.05，`vm`。用細線，col = 色暈 ×1.5。
- **跳鏈**：最多 3 個目標，每跳延遲 40 ms，第 2 跳之後寬度 ×0.75。
- **成本**：一條鏈約 17 點、2 層、1 次 draw。同時 ≤ 4 條。

4. **一擊**：衝撞到目標時，產生一個**火環爆炸**。

**Magnum Drill 式衝擊環**：

### 9.8 全螢幕疊層（擴充 `COMPOSITE_FRAG`）

uniform：
- `uOv`：vec4，五種疊層的強度，依序是 fire、poison、frost、electric，第五種 tint 另外給。
- `uTint`：vec4，rgb 是顏色，a 是強度。
- `uEdgeColor`、`uEdge`：05b 已提出。
- `uZoomBlur`：05b 已提出。

各疊層全部用合成 pass 裡的同一組 fbm（2 octave，可以共用）：

| 疊層 | CSO 對應 | 公式（`r2 = dot(cc, cc)`，`n` 是 fbm） | 顏色 |
|---|---|---|---|
| `fire` | Zombiflame | `m = smoothstep(0.10, 0.42, r2 + (n - 0.5)*0.25)`；n 的 uv 往上捲 0.6/s；`col += mix(c1, c2, n) * m * amt * (0.8 + 0.2*sin(time*23))` | c1 (2.4, 0.8, 0.1)，c2 (4, 2.2, 0.5) |
| `poison` | Zombipoison | `m = smoothstep(0.16, 0.36, r2 + (n - 0.5)*0.4)`，斑駁邊緣。上緣多一條往下的滴落：`drip = step(0.7, fract(uv.x*7 + hash))*smoothstep(0.0, 0.25, uv.y - 0.75)` | `col = mix(col, vec3(0.45, 0.9, 0.1), m*amt*0.7)`。用 mix 而不是 add，做出 CSO 那種不透明的綠斑 |
| `frost` | 冰凍 | 邊緣用 Voronoi 裂紋（低成本：fract 加 2×2 cell 的距離），`m = smoothstep(0.2, 0.45, r2 + edges*0.1)` | 白青 (0.8, 1.0, 1.15)，用 mix 0.5 |
| `electric` | 紫色電光邊框 | `ridge = 1 - abs(n*2 - 1)`；`arc = pow(ridge, 12)`，只取 `r2 > 0.2` 的區域；每 50 ms 換一次噪聲種子（閃爍） | (2, 0.7, 3.5) 或元素色 |
| `tint` | 夜視、殭屍視角、火雨的橘霧、聲波的紫 | `col = mix(col, col*uTint.rgb*1.6 + uTint.rgb*0.05, uTint.a)` | 依情境 |
| `edge` | Lycaon 的藍框、增益框 | 05b §8.11 | 元素色 |

- **成本**：所有疊層共用 1 次 fbm 取樣，大約多 30–40 個 ALU。
- 強度為 0 時用 `if (dot(uOv, uOv) > 0.0)` 跳過整段。
- **閃光安全**：`fire` 的 23 Hz 閃爍振幅只有 ±20%，不算全螢幕閃光。真正的全螢幕閃光（`flashColor`）維持「每秒 ≤ 3 次」的規則（05b §8.11）。

**守則**（延續 05b §8.14 與 06a）：
- 同一個像素上疊的加算層 ≤ 4。
- 單張卡片的面積 ≤ 25% 螢幕。中央 15% 區域的加算亮度 ≤ 2.0。
- 新增的 draw call：`atlasPremium` 層 1、groundfx 1、trail 1、beam 與 bolt 1、meshfx 依物件數（≤ 3），總共 ≤ 7。
- 光源只用 `LightPool`，不新增燈。持續發光的東西（補給箱、靈體、光柱）**一律用 emissive 加 bloom**。
